# PRD — APP 接入统一网关并重构来源选项

## 背景

已在 VPS(`https://radio.hku.wtf`)部署服务端统一网关 `radio-proxy`,它把云听、蜻蜓 FM、全球电台(radio-browser)三个来源整理成 APP 内部已有的共享模型(`Channel`/`Program`/`Province`/`Category`)+ 云听式 `ApiResponse{code,message,data}` 包装,并对全球电台直播流做透明反代。

本任务让 APP 停止直连各来源官方接口,改为统一走网关;同时新增全球电台为第三来源,并把设置页"电台来源"从 pill 按钮改成与"所在城市"一致的下拉菜单。

## 目标

1. APP 网络层统一指向网关,不再直连 `ytmsout.radio.cn` / `rapi.qtfm.cn`,不再在客户端做云听签名。
2. 新增第三来源"全球电台"(`radiobrowser`),复用现有 `Province`/`Category` 维度呈现(国家→地区、标签→分类)。
3. 设置页"电台来源"改为下拉菜单,视觉/交互与"所在城市"下拉一致(TV D-pad 焦点适配)。

## 范围内

- 新增单一网关 API 与对应 Retrofit/OkHttp 装配。
- 三个来源统一经网关取数;`source` 作为 query 参数区分。
- `RadioSourceType` 增加 `RADIOBROWSER` 项。
- 全球电台无节目单(EPG):节目单区域在该来源下隐藏或呈现空态。
- 全球电台回放:无回放能力,回放入口在该来源下不可用。
- 蜻蜓回放两段式:走网关 `/v1/replay` 解析。
- 设置页来源下拉 UI 改造。

## 范围外

- 服务端网关改动(已完成)。
- HLS 分片改写(占比极低)。
- 全球电台的 EPG/回放(数据源本身没有)。
- 更新检查(yecao)接口——独立关注点,不动。
- 收藏数据迁移(现有云听/蜻蜓收藏 key 结构保持兼容)。

## 验收标准

1. 三个来源均能经网关加载筛选项(地区/分类)、电台列表、播放直播流;云听/蜻蜓可加载节目单并回放。
2. 全球电台可加载国家/标签筛选、电台列表、播放直播流;其节目单区域隐藏或空态,不崩溃、不显示错误。
3. 切换来源后,筛选项、列表、默认选中项随来源正确刷新(含"全部"哨兵语义)。
4. 设置页来源选项为下拉菜单,遥控可展开、上下选择、确认收起,焦点行为与城市下拉一致。
5. 客户端代码不含云听签名逻辑与各来源官方 base url。
6. 现有云听/蜻蜓收藏在升级后仍可正常读取与刷新。

## 兼容性约束

- 共享模型字段不变(网关输出即对齐这套),UI 层尽量零改动。
- `RadioSourceType.key` 用作 DataStore key 后缀:云听沿用无后缀历史 key,蜻蜓/全球用 `_<key>` 后缀,新增来源不得破坏既有收藏读取。
- 网关地址应集中可配(单点 base url),便于切换环境。
