# 收藏夹跨来源同步

## Goal

让「★ 收藏」视图同时展示云听与蜻蜓 FM 两个来源的收藏电台，用户在哪个来源下都能看到并直接播放全部收藏，不必为了听另一平台收藏的台而反复切换来源。

## Background

当前收藏按来源隔离存储（`favorites` / `favorites_qingting` 两个 DataStore key），ViewModel 仅订阅当前来源那一份，故 ★收藏 视图只显示当前来源的台。用户希望两边收藏在一个视图里统一可见、可播。

## Requirements

- ★收藏 视图显示两个来源收藏的合并列表（云听在前、蜻蜓在后，各自维持原有最近收藏在前的顺序）。
- 在任一来源下，点击 ★收藏 里属于另一来源的台 → **原地直接播放**，不切换当前浏览来源、不重载列表/筛选。
- 跨源播放的台，其节目单刷新、`lastPlayed` 记忆均按该台自身来源路由（用对应来源的接口与城市）。
- 普通浏览（非收藏视图）下的卡片星标只反映**当前来源**的收藏状态，避免两源 contentId 偶然相同导致误标。
- 正在播放面板（PlayerPanel）的星标反映「正在播放台」在其自身来源下的收藏状态。
- 长按收藏/取消仍作用于**当前来源**（你在云听浏览时长按收藏的是云听的台）。
- 老用户既有的两份收藏数据无损升级，无需迁移步骤。

## Out of Scope

- 不做两源「同一电台」的去重/映射（云听与蜻蜓是不同电台库，contentId 不互通，不尝试识别「同一个台」）。
- 不改设置页来源切换逻辑；切换来源仍重载列表（收藏视图在切换后保持关闭，沿用现状）。
- 不引入收藏时间戳做跨源按时间交叉排序。

## Acceptance Criteria

- [ ] 云听下打开 ★收藏，能看到云听 + 蜻蜓两边收藏的台。
- [ ] 云听下点击一个蜻蜓收藏台能正常出声，且浏览中的云听列表/筛选不被清空。
- [ ] 跨源播放后，正在播放面板标题前显示金色 ★（该台在蜻蜓下确为收藏）。
- [ ] 普通浏览云听列表时，星标仅按云听收藏标注，不受蜻蜓收藏影响。
- [ ] 半点/整点自动刷新在 ★收藏 视图下能刷新两源收藏的节目单且不串源。
- [ ] 老用户升级后两份收藏全部出现在合并视图，数据不丢。
