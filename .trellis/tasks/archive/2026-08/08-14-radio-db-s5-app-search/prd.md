# 第5步:APP 接入全源搜索

> 父任务:[08-12-radio-catalog-db](../08-12-radio-catalog-db/prd.md)
> 前置:[第4步 跨来源搜索](../archive/2026-08/08-12-radio-db-s4-search/prd.md)(服务端已上线)
> 事实来源:[radio-proxy/docs/radio-catalog-db.md](../../../radio-proxy/docs/radio-catalog-db.md)

## Goal

搜索不再受「当前地区 + 当前分类」限制,**一次搜遍当前来源的整份目录**。

## Requirements

用户 2026-08-14 定的范围:

> 只搜索当前来源,但是可以跨区域跨分类搜索。

即:搜索的范围从「来源 + 地区 + 分类」放宽到「**来源**」,来源那一维不放宽。

## 范围(2026-08-14 定)

| 决定 | 选择 |
|---|---|
| 搜索范围 | **当前来源的整份目录**,跨地区跨分类。**不是**第 4 步那个 `source=all` |
| 收藏刷新 | **一并解决**(见下)。服务端要改一处 |
| 做到哪里 | APP + 服务端配套改动,两个仓库一起 |

### 为什么这不是「改个参数」就完事

「搜遍当前来源」这件事,今天**三个来源一个都够不着**(2026-08-14 实测 `/v1/provinces`):

| 来源 | `provinceCode=0` 是什么 | 后果 |
|---|---|---|
| 云听 | 上游真实的「国家」桶,**19 台**,列表里叫「国家」 | 传 0 只搜得到 19 台,**静默** |
| 蜻蜓 | 「全部」哨兵,但 APP 主动过滤掉了不展示 | UI 上够不着 |
| TuneIn | 地区列表里**根本没有 0 这一项**(179 个国家) | UI 上够不着 |

所以服务端必须给出一档明确的「整个来源」范围,APP 搜索走它 —— 不能靠客户端传 `provinceCode=0`
去凑,那对云听是错的,而且错得没有任何报错。

### 收藏刷新那条路(用户已决定顺带解决)

收藏刷新靠 `FavoriteChannel.provinceCode` 分组调 `/v1/channels/by-ids`
(见 `BaseRadioSource.refreshFavoritePrograms`)。跨地区搜到的台被收藏时,APP 手上
**没有它真正的地区**,只有当前筛选栏选中的那个 —— 填进去就是错的:

> 在云听「北京」下搜到「广东交通」并收藏 → 记成 provinceCode=110000 →
> 刷新时按 110000 查 by-ids 查不到 → 这条收藏的「正在播放」**永远是旧的**,不报错。

这与第 4 步那个坑同类:**错得静默**。本步一并解决,机制在 design.md 定。

## Constraints

- 父任务 Constraints 适用。
- **`RadioSourceType` 不加第四个枚举值。** 它随 `FavoriteChannel` 持久化、决定 DataStore
  的偏好键后缀、还有 `DEFAULT` 回退语义 —— 加一个「全部」进去会漏进收藏存储和默认来源。
- 现有的「范围搜索」端点语义不动(第 4 步已经定死:`/v1/search` 的旧参数组合逐字节不变)。
- 旧版 APP 必须照常工作:服务端新增的一律是新参数 / 新字段,不改旧响应。

## Acceptance Criteria

- [ ] 在任一来源的任一地区/分类下搜索,结果覆盖**该来源的整份目录**
      (云听要能搜到 943 台里的任意一台,不是 19 个国家台)
- [ ] 拼音(全拼 / 首字母)、中文子串、英文子串行为与现状一致
- [ ] 搜到的台可以直接播放,起播路径与从列表里点开完全一致
- [ ] 搜到的台可以收藏,且收藏后的「正在播放」副标题**能正常刷新**
- [ ] 退出搜索后回到原来的地区/分类列表,筛选选中态没有被搜索改掉
- [ ] 旧版 APP 打新服务端、新版 APP 打旧服务端都不崩(两侧各自的兼容口径见 design.md)
- [ ] 真机验收:TV 遥控(自绘键盘)与竖屏手机(系统输入法)两条输入路径都走一遍

## Notes

- 第 4 步做的 `source=all`(一次搜遍三家)**已上线但目前没有客户端消费者** ——
  本步按用户的范围决定只搜当前来源。那一档留着不动,将来要做「全网搜」时它就位。
- APP 侧跨源路由的底子**已经有了**(收藏页早就跨源合并展示):`playChannel(channel, source)`、
  `toggleFavorite(channel, source)`、`gridKeyOf`、`playingSource` 全是按「来源+频道」成对传的。
  分页列表那一支是唯一写死 `state.selectedSource` 的地方。本步不需要重建这套东西。
