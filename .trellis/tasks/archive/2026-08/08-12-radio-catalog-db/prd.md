# 电台目录入库

> 唯一事实来源:[radio-proxy/docs/radio-catalog-db.md](../../../radio-proxy/docs/radio-catalog-db.md)
> 本 PRD 不复制该文档的实测数据,只承载需求边界、拆分和跨子任务的验收。
> 与该文档冲突时,**以该文档为准**。

## Goal

把云听 / 蜻蜓 / TuneIn 三个来源的电台目录存进数据库,并按来源纵切,逐来源把读取路径切到库。

## Requirements

原始需求两条:

1. **入库五项:台名、图标、分类、地区、来源。** 其余保持现状。
   ⚠️ 这是清单类需求,**一个字都不要添**。上一轮擅自加了「播放地址」,直接引出签名 TTL 整条废支线。
2. **云听和蜻蜓的 subtitle 改用节目单推断**,不再依赖列表接口现给。

过程中补充三条:

3. 跨区域 / 跨来源搜索。
4. 数据可控(上游改字段 / 返空 / 改分页默认值不能变成事后才知道的用户可见故障)。
5. TuneIn 也定期自动爬,不再手动维护 JSON。

## Constraints

全局规则,四个子任务都适用,来源见文档第五节:

1. 装载是唯一写者,服务端只读这四张表。
2. 库里不存运行时配置(`image` 存上游原始 URL,`publicBase` 读取时拼)。
3. 整份替换:单事务 `DELETE WHERE source=?` + 全量 INSERT。不用 UPSERT。
4. 空目录拒绝写入。
5. 任一子请求失败即整轮放弃(半张目录比写不进去更危险)。
6. 抓取 / 转换 / 服务三段分开。
7. 排序留在 Go,不用 SQL `ORDER BY`。
8. 表结构与读取路径三来源统一,差异只体现在调度,代码里不留分支。
9. **带时效的值不进库**(云听签名播放地址、蜻蜓可由 id 推得的地址,都不存)。
10. 表结构一次建成文档第三节的样子(含 `province_code` 主键 + 独立分类联结表),
    **不要**先建 `category_id` 列再 `ALTER TABLE DROP`——那一步不可逆。

## 拆分与顺序

按**来源纵切**,每一步做完自己就能站住(上一轮按技术层次横切,干完两大步没有任何东西能用):

| 子任务 | 内容 | 优先级 |
|---|---|---|
| [第1步 蜻蜓](../archive/2026-08/08-12-radio-db-s1-qingting/prd.md) | 建表 → 装载 → subtitle 推算 → 定时+告警 → 读取切库 | ✅ 2026-08-13 |
| [第2步 云听](../08-12-radio-db-s2-yunting/prd.md) | 同一条链路 + 320 次枚举 + 起播时解析播放地址 | ✅ 2026-08-13 |
| [第3步 TuneIn](../08-12-radio-db-s3-tunein/prd.md) | 入库 + 读取切库 + 每周自动爬 | ✅ 2026-08-13 |
| [第4步 跨来源搜索](../archive/2026-08/08-12-radio-db-s4-search/prd.md) | 服务端 `/v1/search?source=all` | ✅ 2026-08-14 |
| [第5步 APP 接入全源搜索](../08-14-radio-db-s5-app-search/prd.md) | 搜索跨地区跨分类(**只搜当前来源**)+ 服务端 `scope=catalog` | P3 |

顺序约束(父任务负责守住):

- 第 1 步必须先做完:它验证链路形状,第 2 步是复制。
- **每个来源的「读取切库」和「subtitle 换来源」必须在同一子任务内做完。**
  先切读取后换 subtitle,APP 上「正在播放」那行会空——用户可见的功能退化。
- 第 3、4 步不阻塞前两步。
- **第 5 步的服务端改动必须先于 APP 发版上线**:新 APP 不再发地区/分类,旧网关又不认
  `scope`,两个默认值一撞会让云听的搜索静默退化成只搜 19 个国家台
  (见 [第5步 design.md](../08-14-radio-db-s5-app-search/design.md) 第 7 节)。
