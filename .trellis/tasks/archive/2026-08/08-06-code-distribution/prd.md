# 激活码分发：管理页导出 + App 购买入口

## Goal

把「激活码怎么到用户手里」这条链路补完整，两端各一件事。用户原话：

> 我希望 web 可以批量导出激活码为 txt，一行一个，然后在 APP 端我需要提供一个购买激活码的网页入口，
> 对于手机视图，可以设置一个跳转链接（https://pay.ldxp.cn/shop/hkuai）的按钮，对于电视端，
> 我觉得应该展示一个二维码，手机扫码跳转到网页。

- **管理员侧**：一次生成一批码后，导出成 txt 发给发货渠道，不必手动一个个复制。
- **用户侧**：在 App 里能找到「去哪买码」，手机直接跳链接，电视扫码。

## 背景 / 已确认事实（代码库证据）

- **管理页已经持有全量激活码**：`admin_ui/app.js` 的 `loadCodes()` 一次拉全量存进 `codes` 数组，
  状态筛选与文本搜索都是前端过滤。导出**不需要新增任何后端接口**，直接从内存里的数组生成文件即可。
- **管理页是纯手写 HTML/CSS/原生 JS + `embed.FS`**，无构建链、无 CDN（`08-06-activation-admin-web`
  的架构决策）。导出必须用浏览器原生能力（`Blob` + `<a download>`），不能引第三方库。
- **App 目前没有任何二维码能力**：全项目搜不到 zxing / qrcode 相关代码或依赖
  （`gradle/libs.versions.toml` 里也没有）。
- **手机 / TV 的分流已有现成判据**：`SettingsScreen.kt:339` 的
  `Context.hasTouchScreen()`（读 `PackageManager.FEATURE_TOUCHSCREEN`），
  现在用于决定激活码输入走网格键盘还是系统输入法。本任务复用同一判据，不另造一套。
- **设置页的 TuneIn 区块**只在选中 TuneIn 来源时出现（`SettingsScreen.kt:171`），
  内含「TuneIn 代理」开关与「管理激活码 / 输入激活码」条目。购买入口应并入这一区块。

## 关键产品决策（已与用户确认）

| 决策点 | 结论 | 理由 |
|---|---|---|
| 导出范围 | **只导出「未使用」状态的码** | 贴合发货场景：要发给买家的就是没人用过的。已激活/已过期/已吊销的码混进去只会发错 |
| 二维码生成 | **引入 `com.google.zxing:core`** | 业界标准、纯 Java 无 Android 依赖、约 530KB（TV 应用可忽略）。手写编码器要 ~500 行 Reed-Solomon/掩码/格式信息，出错代价高且长期自己维护；预生成图片则链接一改就得重出图并发版 |
| 购买入口显示时机 | **选中 TuneIn 时总是显示** | 未激活的人要买，已激活的人也可能续期或再买一个给家人 |
| 手机 vs TV | 手机直接跳浏览器；TV 弹二维码 | 用户指定的形态 |

## Requirements

### 管理页：导出未使用激活码

1. 激活码页新增「导出未使用」按钮，导出内容为**纯文本、一行一个码**，无表头、无引号、无备注。
2. 导出范围**固定为 `status === 'unused'`**，不受当前状态筛选与搜索框影响 —— 按钮文案要带上条数，
   让管理员点之前就知道会导出几个。
3. 无未使用的码时按钮置灰，不产生空文件。
4. 文件名带日期，且必须是 ASCII 安全的（跨系统下载不出乱码）。
5. 不新增后端接口、不引第三方 JS 库 —— 用 `Blob` + `<a download>`，用完释放 object URL。

### App：购买激活码入口

6. 设置页 TuneIn 区块新增「购买激活码」条目，位置紧随「管理激活码 / 输入激活码」之下。
7. **触摸设备**：点击直接用系统浏览器打开 `https://pay.ldxp.cn/shop/hkuai`。
8. **非触摸设备（TV）**：点击弹出二维码弹窗，手机扫码即可跳转。
9. 二维码必须**在本地生成**、不联网取图 —— 想买码的场景本就可能是网络受限（TuneIn 代理的目标用户），
   依赖联网取二维码会在最需要它的时候失效。
10. 二维码弹窗同时**以文本形式展示链接原文**：扫码失败时用户还能手动输入；这也是手机端打不开
    浏览器时的兜底。
11. 触摸设备上若没有可用浏览器（`ActivityNotFoundException`），**回落到同一个二维码弹窗**而不是
    静默失败或崩溃。
12. 购买链接作为单一常量维护，不散落在多处。

## Non-goals（明确不做）

- 不做「购买后自动发码」「订单查询」等与支付页对接的流程 —— 本任务只提供一个入口链接。
- 不做导出 CSV/Excel，也不导出备注、到期时间等字段（用户要的就是一行一个码）。
- 不做导出后自动标记「已发货」之类的状态流转（现有 schema 没有这个概念，要做得单独立项）。
- 不新增后端接口，管理页导出全部在前端完成。
- 不做二维码的品牌化定制（Logo、配色），能扫就行。
- 不改激活码的生成、兑换、解绑逻辑。

## Acceptance Criteria

- [ ] 管理页激活码列表上有「导出未使用」按钮，文案含未使用码的条数。
- [ ] 点击后下载一个 `.txt`，内容为纯激活码、一行一个、行数等于按钮上的条数。
- [ ] 导出内容**只含未使用的码**：先把筛选切到「已吊销」再点导出，导出的仍是未使用的那批。
- [ ] 库里没有未使用的码时，按钮为禁用态，点不出空文件。
- [ ] 下载的文件名是 ASCII 安全的、且带日期。
- [ ] 管理页仍无任何第三方 JS 依赖、无新增后端接口（`git diff` 可核对）。
- [ ] App 设置页选中 TuneIn 时可见「购买激活码」条目，**未激活与已激活状态下都可见**。
- [ ] 手机上点击 → 系统浏览器打开 `https://pay.ldxp.cn/shop/hkuai`。
- [ ] TV（无触摸屏）上点击 → 弹出二维码弹窗，**用手机相机能扫出并跳转到该链接**（真机实测，
      不能只看图渲染出来了）。
- [ ] 二维码弹窗里同时能看到链接文本原文。
- [ ] 二维码在深色主题下**依然可扫**（深色底上画深色码是扫不出来的，见 `design.md`）。
- [ ] 飞行模式下打开二维码弹窗，二维码照常显示（本地生成，不联网）。
- [ ] `./gradlew testDebugUnitTest assembleDebug` 全绿；`cd radio-proxy && go test ./...` 全绿。

`embed.FS` 打包进二进制），push 后需手动部署到 `radio.hku.wtf`。App 改动需发版。两者**互不依赖**，
可各自独立上线。
