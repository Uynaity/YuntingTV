# 第3步:TuneIn 统一形态

> 父任务:[08-12-radio-catalog-db](../08-12-radio-catalog-db/prd.md)
> 事实来源:[radio-proxy/docs/radio-catalog-db.md](../../../radio-proxy/docs/radio-catalog-db.md) 第四、六节

## Goal

TuneIn 已经有本地目录,是三个里最不急的。收益是**统一形态**(与另外两个源同表同读取路径)
+ **每周自动爬**,不再手工维护 JSON 文件。

## Requirements

1. **爬虫产物入库**:23215 台,写入五项。带 `TUNEIN_PARTNER_ID` 可在单个 IP 下一次爬完
   → 不需要 IP 池、不需要增量爬。
2. **读取切库**,退休内存目录树。
3. **每周自动爬** + 失败告警。
4. **抓取 / 转换分开**:爬虫只负责抓,转换是纯函数。把转换焊进爬虫 =
   让「改一条清洗规则」去付「重爬一遍全球」的钱。

TuneIn 没有节目单,**不受 subtitle 前置约束**。

> ⚠️ 更正(2026-08-13 实测):subtitle 不是来自 `current_track`,而是来自 `subtext`
> ——现有爬虫产物 30081 行里 `current_track` **0 条有值**、`subtext` **30081 条有值**,
> `toChannel` 走的一直是兜底分支。`subtext` 是电台简介(「Une Voix Pour Tous !」),
> 静态值,**入库不违反契约 9**。`playbill.go` 顶部同样的说法一并更正。

## 规划期确定的两个方案(2026-08-13)

| 决策 | 选择 | 理由摘要 |
|---|---|---|
| 爬虫形态 | **用 Go 重写进服务** | 运行镜像是 alpine + 单个 Go 二进制;跑 Python 要装 python3(+50MB)、COPY `tools/`、把 `./data` 改可写卷。而重写规模比看上去小:genre 那套(两大坨正则 + overrides + `fill_genres`)实测产出恒空,整个不移植 |
| 爬取产物 | **不落 JSON,抓完直接转换入库** | 与蜻蜓/云听同形(fetch → 纯函数转换 → `writeCatalog`);要求 4 由函数边界保证,不由文件保证。代价:一轮失败即整轮作废,库里留上一轮 |
| 分类 | **移植归类规则,真把分类入库** | 上游今天返 `genre_id`(见上面那条更正),不移植等于「五项」里的分类对 TuneIn 是空的。每个 genre 一次 Browse 取名(约 +300 次/周),按名字归入音乐/谈话节目/体育三档 |

⚠️ 分类是**功能变化,不是回归**:APP 上 TuneIn 会从「只有全部一档」变成多出两三个分类入口。
`Categories` 的逐字节等价性验收因此改为「用 2026-07 那份旧产物比读取路径」(见 design 第 7 节)。

细节与其余决策见 [design.md](./design.md)。

## Constraints

- 父任务 Constraints 全部适用。
- TuneIn 实测事实(**不用重测**):
  - 目录是人工维护的地点树,层级不定深,遍历要 3000+ 次 Browse,上游按 IP 计配额。
  - **147 个 guide_id 挂在两个以上国家下(去重后 125 个)** → 这正是 `province_code` 进主键的理由;
    只用 `(source, content_id)` 会让后写的国家覆盖先写的。
  - ~~两份爬虫产物的 genre 字段都是空的 → 联结表对 TuneIn 写 0 行~~
    **作废(2026-08-13 实测)**:上游今天照常返 `genre_id`(波兰 231/232、柬埔寨 1/1、
    卢森堡 13/13)。空的是那两份 2026-07 的产物本身,不是上游的形状。
    → **分类要真入库**(见下面的决策表),联结表对 TuneIn 不再是 0 行。
  - 切库后 `Channels(全部地区)` 取 23215 行耗时 36ms,单地区(8326 台)16ms,
    每范围每 30 分钟才查一次 → **不需要为它加内存缓存**。
- 播放地址仍是起播时调 `Tune.ashx`,现状不变,不进库。

## Acceptance Criteria

- [ ] 23215 台入库,那 125 个跨国台在**每一个**所属国家的列表里都在
- [ ] 分类联结表对 TuneIn 是 0 行(不伪造)
- [ ] 读取切库:`Provinces` / `Categories` / 具体地区 `Channels` 与切库前逐字节一致;
      全部地区的 23215 台集合完全相同(**同名台内部次序不同不是回归**——
      旧实现用不稳定的 `sort.Slice`,连跑两次基线都不同;按 `(Title, ContentID)` 定序后才可复现)
- [ ] 内存目录树删除,不再手工维护 JSON(`tools/` 的 Python 爬虫与 `./data` 卷一并退休)
- [ ] 每周自动爬在位,失败可被发现(库里留上一轮数据 + `/admin/catalog` 陈旧度)
- [ ] 起播路径不变,`Tune.ashx` 正常
