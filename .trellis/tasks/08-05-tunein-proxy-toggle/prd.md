# TuneIn 代理开关

## Goal

TuneIn 直播原本一律经服务端 `radio-proxy` 的 `/proxy/{guideId}` 透传（README 已记录：
"`/proxy/` 是持续带宽消耗(音频长连接)，按并发听众线性增长"）。改为**默认直连**解析出的上游
真实流地址以降低服务器带宽成本，并提供一个**客户端设置开关「TuneIn 代理」**：开 = 走服务端
透传，关（默认）= 直连，供直连不可达的网络环境手动兜底。

> 变更记录（2026-08-05）：原方案是「TuneIn 直连」开关、默认关闭走代理。因功能尚未对外
> 上线，直接把默认态改为直连、开关语义反转为「代理」，并只在选中 TuneIn 来源时展示。
> 不考虑旧版本用户兼容（DataStore key 直接改名，无迁移）。

## 背景 / 约束

- 仅 TuneIn 受影响：云听（`yunting`）、蜻蜓FM（`qingting`）播放地址本就是上游直链，
  从未经过 `/proxy/` 透传，不在本次范围内。
- 服务端 `/v1/stream`（`radio-proxy/gateway.go:handleV1Stream`）针对 `source=tunein`
  内部已经调用 `resolveStreamURL` 解出真实上游地址，但目前把它丢弃、只回传拼好的
  `/proxy/{id}` 地址。把这个已解析出的地址下发给客户端零额外网络开销。
- 直连地址在部分网络环境下可能不可达（`radio-proxy/handlers.go:19` 已有先例：
  "用户手机直连可能不可达；经此透传"）——这正是当初做代理透传的原因之一，
  所以保留代理开关作为手动兜底，且**不做自动可达性探测**。
- 已决定：直连播放失败时**不自动降级到代理**，按现有播放失败路径提示用户，
  用户需自行去设置里关闭开关。避免本轮引入播放器错误监听/重试的额外复杂度。

## Requirements

- 服务端 `/v1/stream` 响应对 `source=tunein` 额外下发已解析出的真实上游地址
  （新增字段，如 `directUrl`）；其余来源该字段留空。字段是新增的，不改动、
  不删除现有 `url` / `streamType` 字段 —— 旧客户端可安全忽略。
- 客户端新增持久化设置项：「TuneIn 代理」开关，默认**关闭**（= 直连）。存储上是全局项
  （值不随来源切换重置），但**仅在当前电台来源为 TuneIn 时展示**，位置紧邻「电台来源」下方。
- 客户端起播 TuneIn 电台时，若开关关闭且服务端下发了 `directUrl`，使用该地址播放；
  开关开启，或 `directUrl` 缺失/为空（如旧网关部署），一律回退 `/proxy/` 透传地址链路，
  不视为异常。
- 直连模式下 HLS 与 progressive 两类 TuneIn 台都要能正常起播（真机验收各挑一台）。
- 不引入自动降级/重试逻辑；直连失败沿用现有播放失败提示与用户可重试路径。

## Non-goals

- 自动探测网络可达性、自动在直连/代理间切换。
- 服务端侧全局强制策略（如按部署环境批量关闭代理）。
- 除新增该字段外，不改动 `/proxy/`、`/seg` 现有透传与 HLS 改写逻辑。

## Acceptance Criteria

- [ ] 设置页在「电台来源」下方新增"TuneIn 代理"开关，默认关闭；选中云听/蜻蜓时该项不出现，
      切回 TuneIn 后重新出现且状态保持。
- [ ] 默认（开关关闭）起播 TuneIn 电台使用真实上游地址而非 `/proxy/{id}`（可通过网络请求/日志
      验证未命中 `radio.hku.wtf/proxy`）。
- [ ] 默认态下 HLS 台与 progressive 台各挑一个真机验证可正常起播、无缓冲卡死。
- [ ] 开启开关后回到 `/proxy/{id}` 透传链路，播放正常。
- [ ] 网关未下发 `directUrl`（模拟旧网关部署）时，开关关闭也不影响播放，正常回退代理地址。
- [ ] `go test`（radio-proxy）、客户端单测、lint、`assembleDebug` 全绿。
- [ ] 直连失败时的表现与现有播放失败路径一致（人工触发一次断网/不可达场景观察，非新增代码路径）。

## Notes

- 该功能是纯增量：字段新增、开关新增，不改变任何现有默认行为，回滚成本低
  （摘掉开关 UI + 服务端不下发字段即可）。
- `radio-proxy` 不在版本控制内（根 `.gitignore` 忽略，按项目所有者决定），本轮服务端改动
  需额外记得部署到 `radio.hku.wtf` 才对线上客户端生效。
